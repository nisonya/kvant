# Kvant Server

> **База данных, HTTPS, API, JWT**

> **В двух словах:** установите **MySQL** → разверните **Kvant Server** → в настройках приложения задайте **`DATABASE_CONN`**, **`API_PORT`**, пути к папкам для **сохранения файлов**. Для доступа клиентов из другой сети настройте **проброс порта**. В **Kvant Desktop** пользователи указывают **URL** вашего сервера.

## Что делает репозиторий

- развёртывает и инициализирует БД;
- поднимает HTTPS API для клиентов Kvant;
- создаёт пользователя по умолчанию (потом его нужно удалить).

### Перед установкой — проверьте окружение

Совместимая ОС (Windows/Linux — по финальному установщику) · сеть до клиентов · место под БД и бэкапы · открытый порт API · права администратора на время установки.

## Инструкция по установке

### 1. Установка MySQL

> **Главное:** MySQL ставится на машину, где будет **Kvant Server**. Порт по умолчанию — **3306**. Пароль администратора (**root** или выбранного при установке пользователя) сохраните в надёжном месте.

#### Windows

| Шаг | Действие |
| --- | --- |
| 1 | Скачайте **MySQL Installer** с [официального сайта](https://dev.mysql.com/downloads/installer/). |
| 2 | В мастере отметьте **MySQL Server** (при необходимости — MySQL Shell). |
| 3 | Альтернатива: `winget search mysql` → `winget install …` (имя пакета сверьте по выводу). |
| 4 | Задайте и **запишите** пароль администратора (часто **root**). |

#### Linux (Debian / Ubuntu и близкие)

| Шаг | Команда / действие |
| --- | --- |
| 1 | `sudo apt update && sudo apt install mysql-server` |
| 2 | `sudo systemctl enable --now mysql` (иногда сервис называется `mysqld` — см. ваш дистрибутив) |
| 3 | При необходимости выполните `mysql_secure_installation` |

Вход администратора в консоль MySQL (см. также [ниже](#как-зайти-в-mysql-из-консоли-терминала)): **`sudo mysql`** или **`mysql -u root -p`**.

### 2. Пользователь БД и подключение (DATABASE_CONN)

> **Главное:** **базу данных вручную не создавайте** — приложение создаёт её сама при первом запуске (достаточно работающего MySQL и корректной строки **`DATABASE_CONN`** в настройках). Имя базы в строке подключения обычно указывают то, какое должно использовать приложение — о создании схемы позаботится сервер.

#### Root или отдельный пользователь

| Вариант | Когда подходит |
| --- | --- |
| **Пользователь `root`** | Проще для проверки и внутренних стендов: используйте логин `root` и пароль из установки MySQL в **`DATABASE_CONN`**. На продакшене **не рекомендуется**. |
| **Отдельный пользователь** | Предпочтительно для эксплуатации: свой логин/пароль, минимально достаточные права — так безопаснее, чем `root`. |

Отдельного пользователя **создавать необязательно**: если указать в **`DATABASE_CONN`** учёт **`root`** (и верный пароль), этого достаточно для первого запуска.

#### Как зайти в MySQL из консоли (терминала)

Нужно, чтобы команда **`mysql`** была в `PATH` (на Windows может понадобиться «MySQL Command Line Client» из меню Пуск или полный путь к `mysql.exe`). Сервер MySQL должен быть **запущен**.

**Windows (cmd / PowerShell):**

```bash
mysql -u root -p
```

Введите пароль root — должна открыться консоль с приглашением `mysql>`.

**Linux:**

```bash
sudo mysql
```

или, если включён вход root по паролю:

```bash
mysql -u root -p
```

Выйти из консоли MySQL: **`exit`** или **`quit`**.

#### Как создать отдельного пользователя под приложение

Подключитесь как администратор (`root` или `sudo mysql`). **Команду `CREATE DATABASE` не выполняйте** — база появится при работе приложения.

Пример для локального сервера (`localhost`). Подставьте свои `имя_пользователя` и **`надёжный_пароль`**:

```sql
CREATE USER 'имя_пользователя'@'localhost' IDENTIFIED BY 'надёжный_пароль';
GRANT ALL PRIVILEGES ON *.* TO 'имя_пользователя'@'localhost';
FLUSH PRIVILEGES;
```

`GRANT ALL ON *.*` удобен, когда приложение само создаёт базу и объекты; в закрытых установках это часто допустимо. При внутреннем регламенте безопасности сузьте права или сверьтесь с документацией вашего релиза Kvant.

Если приложение и MySQL на **разных** машинах, вместо `'localhost'` задайте хост или подсеть; для удалённого доступа настройте `bind-address` MySQL и сетевой экран для порта **3306**.

#### Строка `DATABASE_CONN` в настройках приложения

В интерфейсе сервера указывается **`DATABASE_CONN`**. То же значение иногда задают в конфигурации или `.env` под другим именем (например **`DATABASE_URL`**) — смотрите вашу сборку.

Типичный формат строки подключения:

```text
mysql://USER:PASSWORD@HOST:3306/ИМЯ_БД
```

Пример для отдельного пользователя на той же машине:

```text
mysql://имя_пользователя:надёжный_пароль@127.0.0.1:3306/kvant
```

Пример для **`root`**:

```text
mysql://root:ваш_пароль_root@127.0.0.1:3306/kvant
```

Спецсимволы в пароле кодируйте в URL (например `@` → **`%40`**). Живые пароли не коммитьте в git.

Имя базы (`kvant` в примерах) — то, как база будет названа приложением при автоматическом создании; выполнять **`CREATE DATABASE` вручную не нужно**.

#### Как проверить подключение к MySQL **до** запуска приложения

Из **обычной** консоли ОС (до приглашения `mysql>`):

```bash
mysql -h 127.0.0.1 -P 3306 -u имя_пользователя -p
```

После ввода пароля должен открыться сеанс без ошибки **`Access denied`**. Краткая проверка одной строкой:

```bash
mysql -h 127.0.0.1 -P 3306 -u имя_пользователя -p -e "SELECT VERSION();"
```

Если здесь ошибка авторизации или «не удаётся подсоединиться», исправьте учётную запись или сеть **до** подстановки строки в **`DATABASE_CONN`** и запуска Kvant Server.

#### Как понять, что приложение дошло до БД после запуска

- Сервер стартует **без** ошибок подключения к MySQL в логах.
- Отвечает HTTP API по проверке в браузере (см. следующий раздел).

### 3. Архив, установщик, запуск

> **Главное:** скачайте архив **Kvant Server** из этого репозитория под свою ОС; установите на машину-сервер. В настройках приложения укажите **`API_PORT`** (совпадает с пробросом порта при доступе извне), строку **`DATABASE_CONN`**, пути к папкам для хранения файлов. Сохраните **адрес API** для клиентов.

Проверка API (путь и ответ могут отличаться в вашей сборке):

```text
http://localhost:<API_PORT>/
```

Пример текста успешного ответа:

```text
API WORK
```

### 4. Возможные ошибки

> **Главное:** проверьте **доступность порта API**, **URL** в клиенте и **работу MySQL**; затем корректность **`DATABASE_CONN`**, логина и пароля; для пользователя без широких прав — достаточно ли **полномочий** для автоматического создания базы и объектов.

| Симптом | Что проверить |
| --- | --- |
| Таймаут / «не подключается» в клиенте | API запущен; верный **URL и порт**; сеть и брандмауэр. |
| Ошибка входа в API | Адрес сервера; учётная запись приложения; не перепутаны **HTTP и HTTPS**. |
| Нет связи MySQL с сервера приложения | Служба MySQL запущена; **`DATABASE_CONN`** (хост, порт **3306**, логин, пароль, имя БД без опечаток); удалённое подключение — `bind-address`, сеть, совпадение **`'user'@'host'`** с источником подключения. |
| `Access denied` (MySQL) | Пароль; что пользователь существует для того **хоста**, с которого подключается приложение (**`localhost`** vs IP). Проверка: **`mysql -h … -u … -p`** из консоли. |
| Ошибки «нет прав», «unable to create database» | Для пользователя недостаточно привилегий авто создания базы и схемы — временно проверить под **`root`** или усилить `GRANT` по регламенту. |
| В Desktop не пишутся вложения / файлы | В настройках клиента указаны **папки**; права на диск; антивирус. |
